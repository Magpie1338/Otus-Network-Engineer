### 1.2 Связность

- Внутри участков: full-mesh p2p Ethernet-линки (в каждой паре 1–2 параллельных линка = сети EVE-NG).
- Межучастковые (eBGP) линки: Москва↔Киторн, Москва↔Ламас, Киторн↔Ламас, Киторн↔Триада, Ламас↔Триада, СПб↔Триада (×2), Триада↔Чокурдах (×2), Триада↔Лабытнанги.
- User-сегменты: VPC1, VPC7 (Москва), VPC8, VPC (СПб), VPC30, VPC31 (Чокурдах) — по одному VPC на access VLAN.
- L2 fabric: SW2/SW3 (access) ↔ SW4/SW5 (distribution, Москва); SW9/SW10 (СПб); SW29 (Чокурдах).

## 2. Суперсеть (supernet)

**Суперблок лабы: `10.5.0.0/19`** (10.5.0.0 — 10.5.31.255, 8192 адреса).

Выбор:
- Занято участками ~4740 адресов → запас ~42% на расширение.
- /19 целиком вмещает все блоки участков с выравниванием по естественным границам (/22, /23, /26).
- Если появится выход во «внешний мир» (uplink-AS над Триадой), наружу анонсируется один prefix `10.5.0.0/19`.

### 4.2 Конфигурационные команды

#### eBGP-вариант (основной для этой лабы)

На каждом «источнике анонса» — aggregate + заглушка в Null0 (чтобы агрегат существовал при падении части компонент):

```
! R14 и R15 (AS 1001, Москва): суммаризуем весь участок одним /22
ip route 10.5.0.0 255.255.252.0 Null0 250
router bgp 1001
 aggregate-address 10.5.0.0 255.255.252.0 summary-only
 ! neighbor <R22|R21> remote-as <101|301>

! R22 (AS 101, Киторн)
ip route 10.5.24.0 255.255.255.192 Null0 250
router bgp 101
 aggregate-address 10.5.24.0 255.255.255.192 summary-only
 ! neighbor <R23> remote-as 520

! R21 (AS 301, Ламас)
ip route 10.5.24.64 255.255.255.192 Null0 250
router bgp 301
 aggregate-address 10.5.24.64 255.255.255.192 summary-only
 ! neighbor <R24> remote-as 520

! R18 (AS 2042, СПб): /22 в сторону Триады (обоим соседям)
ip route 10.5.4.0 255.255.252.0 Null0 250
router bgp 2042
 aggregate-address 10.5.4.0 255.255.252.0 summary-only
 ! neighbor <R24|R26> remote-as 520

! R23–R26 (AS 520, Триада): свой участок /23
ip route 10.5.8.0 255.255.254.0 Null0 250
router bgp 520
 aggregate-address 10.5.8.0 255.255.254.0 summary-only
 ! по желанию — агрегат соседей Киторн+Ламас одним префиксом:
 ! aggregate-address 10.5.24.0 255.255.255.128 summary-only

! R28 (Чокурдах)
ip route 10.5.16.0 255.255.252.0 Null0 250
router bgp <chokurdah-as>
 aggregate-address 10.5.16.0 255.255.252.0 summary-only
 ! neighbor <R25|R26> remote-as 520

! R27 (Лабытнанги): блок сам является искомым префиксом
router bgp <labtynangi-as>
 network 10.5.20.0 mask 255.255.255.252
 ! neighbor <R25> remote-as 520
```

> Если внутри участка используется iBGP, агрегат поднимается одинаково на всех edge-роутерах участка (у каждого свой Null0-стаб) — иначе при отказе линка одного edge-роутера компонентный роут пропадёт и агрегат перестанет анонсироваться.

#### OSPF-вариант (если участок строится на OSPF с зонами)

Суммаризация `area range` — на ABR, только для inter-area маршрутов:

```
! Москва: ABR на границе area 0 (p2p-fabric) → area 100 (VLANы), R12/R13 как ABR
router ospf 1
 area 100 range 10.5.1.0 255.255.255.0
 area 100 range 10.5.2.0 255.255.255.0

! СПб: аналогично на R16/R17 (ABR между area 0 и VLAN-зонами)
router ospf 1
 area 200 range 10.5.5.0 255.255.255.0
 area 200 range 10.5.6.0 255.255.255.0
```

Агрегат участка целиком (например, «Москва → eBGP-сосед») при OSPF-источнике делается через редистрибуцию со static-суммой:

```
ip route 10.5.0.0 255.255.252.0 Null0
router ospf 1
 network 10.5.0.0 0.0.3.255 area 0
 ! и в BGP соседней AS агрегат приходит как обычный prefix из редистрибуции/static
```

#### Static-вариант (минимум протоколов)

На соседнем роутере достаточно одного суммарного статического маршрута вместо списка подсетей:

```
! R22 в сторону Москвы:
ip route 10.5.0.0 255.255.252.0 10.5.24.1
! R23 в сторону Чокурдаха:
ip route 10.5.16.0 255.255.252.0 10.5.16.2
! R25 в сторону СПб:
ip route 10.5.4.0 255.255.252.0 10.5.4.41
```

## 5. Sanity check

| Проверка | Результат |
|---|---|
| p2p: требуемых адресов 2, ёмкость /30 = 2 usable | OK (ровно, без запаса — по стандарту) |
| VLAN: 1–2 хоста, ёмкость /24 = 254 usable | OK, запас под расширение |
| Сумма блоков ≤ суперсеть /19 | OK: ~4740 из 8192 адресов, запас ~42% |
| Пересечения подсетей | Нет (блоки участков попарно дизъюнктны, p2p внутри /24 не пересекаются) |
| Суммарные префиксы точны (покрывают только свои подсети) | Проверено по таблицам разд. 3: каждый /22–/26 закрывает ровно свой диапазон |
| Суммарный маршрут на границе заменяет N подсетей | Москва /22 ← 2×/24 VLAN + 12×/30 + loopbacks; СПб /22 ← 2×/24 + 11×/30; Чокурдах /22 ← 2×/24 + 3×/30; Триада /23 ← 4×/30 + /28 loopbacks |
| Расхождение схема ↔ .unl | Нет: интерфейсы и линк-соединения совпадают полностью |

## 6. Примечания

- Нумерация VLAN: 101/102 (Москва), 201/202 (СПб), 300/301 (Чокурдах) — не входит в план адресов, предложена для консистентности.
- Management EVE-NG (pnet0/Cloud0) остаётся вне суперсети 10.5.0.0/19 — используется отдельное адресное пространство гипервизора.
- R27 не имеет loopback в плане: единственная точка входа, router-id берётся с интерфейса e0/0 (10.5.20.2).
- Транзитные eBGP-линки принадлежат блокам «листовых» AS (Киторн, Ламас, Чокурдах, Лабытнанги) и блоку СПб — так каждый сосед Триады анонсирует весь свой блок одним aggregate, а сама Триада не содержит чужих линков в своём префиксе 10.5.8.0/23.
